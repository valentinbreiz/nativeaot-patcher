InterruptMaskScope

Masks maskable interrupts on the current CPU for the lifetime of the scope and restores the previous interrupt state on dispose. Obtained from MaskInterrupts(); use it in a using statement around scheduler entry points the manager does not already guard (diagnostics reads, tuning setters), so the timer tick cannot observe a half-mutated run structure.

Interfaces

IScheduler

A scheduling policy: everything that decides which thread runs when. The mechanism around it (the thread registry, the lifecycle transitions, the timer-tick entry, the register save and restore) is fixed. Install an implementation with SetScheduler(IScheduler).

Every hook runs in the kernel's most sensitive window. Most are called with interrupts already masked, and the two scheduling hooks run inside the timer interrupt itself; each member below says which. No hook may block, park, or wait, and none may allocate on the tick path. Four get no mask from the manager (SetPriority(PerCpuState, SchedulerThread, long), GetPriority(SchedulerThread) and the two run-queue diagnostics) and must take MaskInterrupts() themselves before touching the run structure. The spinlock around SetPriority(PerCpuState, SchedulerThread, long) is not a substitute: it excludes another caller, not the tick.

Several hooks have no mechanism-side caller yet, because the kernel runs on one CPU and nothing in-tree sets priorities. Implement them, but do not expect them to be exercised.

Two rules hold for every hook. Each must tolerate being called more than once for the same thread, and each must tolerate an empty SchedulerData slot, because OnThreadExit(PerCpuState, SchedulerThread) clears it and a thread can lose its record between a tick and the hook that observes it; that is why a hook reads the slot with as and never a cast. A record written by a different policy is never handed to a hook: SetScheduler(IScheduler) re-homes every live thread through OnThreadExit(PerCpuState, SchedulerThread) on the outgoing policy and OnThreadCreate(PerCpuState, SchedulerThread) on the incoming one.
