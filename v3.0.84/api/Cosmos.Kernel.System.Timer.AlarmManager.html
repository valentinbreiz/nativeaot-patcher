Class AlarmManager

Namespace
Cosmos.Kernel.System.Timer
Assembly
Cosmos.Kernel.System.dll

Runs callbacks after a delay on a dedicated kernel thread. Alarm callbacks run in thread context, so they may block, allocate and use scheduler primitives, unlike the interrupt-context callbacks of Schedule(Action, TimeSpan). Requires the scheduler; resolution is bounded by the scheduler tick.

The scheduling calls themselves also run in thread context only. Every member here takes the alarm list's mutex and parks if it is held, so calling one from an interrupt handler, a TimerManager callback included, parks inside the handler and hangs. The TimerManager members mask interrupts instead of parking and have no such restriction.

ScheduleRecurring(Action, TimeSpan)

Schedules a callback to run repeatedly with the specified period, in thread context. The period restarts when the callback fires, not when it returns, so a callback that runs longer than the period leaves the next firing already due.

public static ulong ScheduleRecurring(Action callback, TimeSpan period)

Parameters

callback Action

Period between firings; must be positive. Resolution is bounded by the scheduler tick.
